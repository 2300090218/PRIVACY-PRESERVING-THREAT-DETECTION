# Privacy Model & Data Minimization Architecture

## Overview
The platform addresses the classic trade-off between collaborative threat detection and data privacy. Organizations need to detect advanced threats across collective network intelligence without exposing employee usernames, internal network topologies, exact IP addresses, or device identifiers to a third-party central server.

---

## 1. Zero-Raw-Data Central Storage Guarantee
The central PostgreSQL database schema explicitly omits any raw sensitive telemetry tables:
- **No raw usernames** (`username`, `user`, `email` are stripped at the edge).
- **No exact source IPs** (`source_ip` is stripped or masked to `/24` subnet).
- **No physical locations** (`location`, `exact_location` are stripped).
- **No raw device identifiers** (`device_id` is replaced with an HMAC pseudonym).
- **No raw credentials or secrets** (detected secrets cause immediate pre-flight drop).

---

## 2. Configurable Privacy Policies
Every field evaluated by the edge Privacy Gateway is governed by an explicit `PolicyAction`:

| Field Name | Policy Action | Transformation Details |
|---|---|---|
| `username` | **REMOVE** | Completely stripped from telemetry before leaving local boundary |
| `source_ip` | **REMOVE** | Completely stripped from telemetry before leaving local boundary |
| `exact_location` | **REMOVE** | Completely stripped from telemetry before leaving local boundary |
| `device_id` | **PSEUDONYMIZE** | Replaced with non-reversible salted HMAC-SHA256 token (e.g. `DEV-A8F3`) |
| `event_type` | **ALLOW** | Passed through for security event categorization |
| `failed_attempts` | **ALLOW** | Preserved for brute-force sliding window analysis |
| `destination_port` | **ALLOW** | Preserved to analyze service vulnerability target (e.g. port 22, 443) |
| `protocol` | **ALLOW** | Preserved (TCP, UDP, ICMP) |
| `attack_indicators` | **ALLOW** | Threat flags extracted locally (e.g. `SYN_FLOOD`, `AUTH_FAILURE_BURST`) |
| `duration_seconds` | **AGGREGATE** | Coarsened into duration tiers (e.g. `0-10s`, `10-60s`, `60-300s`) |
| `bytes_transferred`| **AGGREGATE** | Coarsened into volume tiers (e.g. `TIER_1_100_TO_1000`) |
| `timestamp` | **ALLOW** | Preserved for chronological sliding-window correlation |
| `risk_score` | **ALLOW** | Preserved for alert prioritization |

## 3. Pseudonymization Mechanics
Device identifiers are transformed using HMAC-SHA256:

$$\text{Pseudonym} = \text{Prefix} \mathbin{\Vert} \text{Truncate}_{8}(\text{HMAC-SHA256}(\text{Salt}_{\text{org}}, \text{RawIdentifier}))$$

- **Deterministic**: The same edge device within Organization A generates the same pseudonym token, allowing local behavioral profiling over time.
- **Unlinkable**: Organization B has a different secret salt $\text{Salt}_{\text{orgB}}$. If the same hardware identifier exists in both organizations, the resulting pseudonym tokens are mathematically independent and uncorrelated.
- **Non-Reversible**: Given `DEV-A8F3`, the central server cannot invert the HMAC to recover the physical machine MAC address or hostname.

---

## 4. Double Safety Boundary

### Boundary 1: Edge Privacy Gateway (`privacy_gateway/`)
- Executes in Organization A's private infrastructure.
- Runs `PrivacyGateway.transform_event()`.
- Runs `validate_protected_payload()`.
- Raises `PrivacyViolationError` locally if prohibited keys or regex patterns (email, AWS keys, Bearer tokens, exact IPs) are present.

### Boundary 2: Central Server Rejection Gate (`backend/app/api/v1/events.py`)
- Independent server-side inspection before Pydantic parsing.
- Actively checks `raw_body.keys()` against `FORBIDDEN_RAW_FIELDS`.
- Validates that string fields (`source`, `device_id`) do not match raw IPv4 patterns.
- Rejects violations with `HTTP 400 Bad Request`.
- Logs `PRIVACY_LEAKAGE_REJECTED` in the immutable central audit trail.

---

## 5. Live Privacy Metrics
All privacy metrics displayed in the dashboard and API are computed directly from operational counters:
- `processed_events`: Total events submitted to local gateways.
- `protected_events`: Total events that passed minimization and were transmitted.
- `removed_fields`: Exact count of fields stripped by `PolicyAction.REMOVE`.
- `masked_fields`: Exact count of fields masked by `PolicyAction.MASK`.
- `pseudonymized_fields`: Exact count of tokens generated by `PolicyAction.PSEUDONYMIZE`.
- `privacy_violations`: Exact count of rejected payloads.
- `transmission_failures`: Exact count of edge retries due to network interruptions.
